# Upgrade to 3.4.0

**Release date: October 30, 2026**

## Applicability

This guide describes the announcement integration changes in 3.4.0.
Use it to update an existing announcement integration or add the announcement
center. If using the SDK's default bell, cards, or announcement page, configure
the local announcement routes they emit, or map those destinations to working
host views. Apps already using announcements should review the applicable
changes below even if they do not add a new menu entry.

For standard SDK applications upgrading from 3.0.x, 3.1.x, or 3.2.x, first choose
[first-time Prediction integration or deferral](3.3.1.md#3-first-time-or-deferred-integration),
then follow the announcement steps below. Prediction is enabled by default;
explicitly keep `features.prediction: false` if you are not adding its routes.
Adding announcements does not require enabling Prediction.

If upgrading from 3.3.0 with Prediction already integrated, first review the
[existing route migration](3.3.1.md#2-migrate-existing-prediction-routes-and-navigation).
If Prediction was never integrated, use the
[first-time or deferred path](3.3.1.md#3-first-time-or-deferred-integration) instead.
Apps on 3.3.1 can proceed to the announcement steps, preserving their existing
Prediction configuration.

Apply the applicable Prediction and announcement instructions with one dependency
update to the final target release; no intermediate installs are needed. Reuse
the existing provider, router, routes, and menus throughout.

For complete examples, use the [Announcement integration and migration guide](../../../packages/ui-notification/docs/integration-guide.md).

## 1. Prepare dependencies and deployment

Align the announcement package and related SDK dependencies using the feature
guide's [dependency and stylesheet requirements](../../../packages/ui-notification/docs/integration-guide.md#dependencies-and-styles).
Check published constraints rather than assuming all packages share a version.

The target backend must support the current announcement list, active-article,
and detail contracts and subscription topics; there is no fallback to older
endpoints or response formats. Confirm the
[deployment requirements](../../../packages/ui-notification/docs/integration-guide.md#4-deployment-requirements)
before rollout.

## 2. Update applicable existing integrations

### Host navigation

Update the existing adapter for announcement-scoped navigation, following the
[navigation contract](../../../packages/ui-notification/docs/integration-guide.md#1-configure-navigation).
If sharing Prediction's adapter, add the announcement branch in the
[shared navigation example](../../../packages/prediction/docs/integration-guide.md#navigation-callbacks)
once and connect the callback to both the existing provider and Scaffold.
Preserve other routes' query/hash behavior.

### Custom UI, hooks, and adapters

Migrate custom carousels from `tips` to `cardTips`, and review unread handling,
initial-load cards, row/category conversions, and custom data sources using the
[custom integration migration table and examples](../../../packages/ui-notification/docs/integration-guide.md#3-migrate-custom-integrations).
Custom bells need a View all or paginated host view for posts beyond the first
server page; Scaffold already supplies this entry.

## 3. Review default behavior and source selection

Review the new `widgetConfigs.announcement.excludeOfficial` setting, which
keeps official announcements included by default. The
[source configuration guide](../../../packages/ui-notification/docs/integration-guide.md#2-register-routes-and-choose-the-source)
covers configuration merging, broker requirements, empty-view behavior, and
`is_official` detail selection. Review the
[custom integration behavior](../../../packages/ui-notification/docs/integration-guide.md#3-migrate-custom-integrations)
for silent initial loading, notification-driven cards, and unread semantics.

## 4. Register routes for SDK announcement destinations

The default bell, cards, and View all action emit list/detail destinations that
need working host views. Follow the
[route setup](../../../packages/ui-notification/docs/integration-guide.md#2-register-routes-and-choose-the-source),
reusing existing routes or mapping destinations to custom views; a separate menu
entry is optional. Registering routes does not create a mobile sidebar item.
To add one, append it to the end of the existing mobile menu by default, following
[announcement navigation entries](../../../packages/ui-notification/docs/integration-guide.md#announcement-navigation-entries).
For custom desktop navigation, check that `mainNavProps.customRender` still renders
`components.notify`; replacing the default layout can otherwise remove the bell.

Custom/legacy rows without slug or source metadata can produce numeric ID links.
The slug route does not automatically switch to ID lookup, and numeric slugs
remain valid. Preserve complete metadata or explicit custom URLs; if retaining
ID navigation, follow the
[legacy ID integration notes](../../../packages/ui-notification/docs/integration-guide.md#legacy-id-destinations).

For first-time integration, use the
[integration checklist](../../../packages/ui-notification/docs/integration-guide.md#first-time-integration-checklist)
and [framework route placement](../../../packages/ui-notification/docs/integration-guide.md#framework-route-placement).
Apps without Prediction can use the
[standalone navigation adapter](../../../packages/ui-notification/docs/integration-guide.md#standalone-navigation-adapter).

A custom mobile return bar is optional host UI, not added by registering routes.
To match the demo, follow the
[mobile return-bar guide](../../../packages/ui-notification/docs/integration-guide.md#optional-mobile-return-bar)
for `Scaffold.topBar`, RTL, and return-destination query cleanup.

## 5. Verify the upgrade

Complete the [full feature verification checklist](../../../packages/ui-notification/docs/integration-guide.md#5-verify-the-integration).
For an existing integration, focus the upgrade review on these changes:

- [ ] The deployed backend supports the current contracts without relying on
      legacy endpoints or response formats.
- [ ] The existing adapter handles announcement scope without changing other
      routes, and all exposed SDK list/detail destinations resolve.
- [ ] Any configured mobile sidebar entry appears once at the intended position
      (the end by default), uses the translated announcement label and bell icon,
      opens the list with the correct locale/basename, and closes the drawer after
      selection. Custom desktop navigation retains `components.notify` and working
      bell/View all links.
- [ ] Custom integrations use the migrated hook fields and row/source metadata;
      source selection, initial-load cards, and unread behavior match the new contracts.
