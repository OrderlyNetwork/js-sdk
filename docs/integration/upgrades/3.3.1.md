# Upgrade to 3.3.1

**Status: Released**

**Release date: October 28, 2026**

## Applicability

This guide covers Prediction host integration when upgrading standard SDK pages
and components to 3.3.1 from 3.0.x, 3.1.x, 3.2.x, or 3.3.0.

| Existing app                              | Steps to follow                                                                                                                                                                                          |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3.0.x, 3.1.x, or 3.2.x without Prediction | Prepare target dependencies, then choose [first-time integration or deferral](#3-first-time-or-deferred-integration). No legacy redirect is needed unless the app previously exposed `/prediction` URLs. |
| 3.3.0 without Prediction integrated       | Prepare target dependencies, then choose [first-time integration or deferral](#3-first-time-or-deferred-integration).                                                                                    |
| 3.3.0 with Prediction integrated          | Prepare target dependencies, then [migrate existing routes and navigation](#2-migrate-existing-prediction-routes-and-navigation).                                                                        |
| Prediction already explicitly disabled    | Preserve the disabled setting unless you intend to enable it.                                                                                                                                            |

Apps without Prediction do not need to add its page as part of this upgrade, but
must explicitly disable the feature if leaving its routes unconfigured. Prediction
is enabled by default, so upgrading can expose SDK navigation entries immediately.

For a first-time integration, use the [Prediction Integration Guide](../../../packages/prediction/docs/integration-guide.md).
The source migration reference is [Migrating from earlier versions](../../../packages/prediction/README.md#migrating-from-earlier-versions).

## 1. Prepare dependencies

Align the related SDK dependencies to the target release's published constraints
and update the lockfile with your existing package manager. Do not assume every
SDK package shares a version number. See [dependency preparation](../../../packages/prediction/docs/integration-guide.md#1-prepare-dependencies-and-the-host-application).

When enabling Prediction, the current integration guide requires
`@orderly.network/prediction` 3.3.1+ and
`@orderly.network/i18n` 3.3.1+ for the `common.predict` menu label. i18n 3.3.0
does not contain that key. If your app supplies custom locale resources, refresh
the Prediction resources from the target release, including `common.predict`,
`prediction.probability`, and `prediction.column.last&probability`.

When upgrading directly to a later compatible release, use that target release's
dependencies; you do not need to install 3.3.1 first. If deferring Prediction,
update the SDK packages your app already consumes without adding a direct
`@orderly.network/prediction` page dependency just for this checklist.

## 2. Migrate existing Prediction routes and navigation

This section applies to apps that already expose the old `/prediction` page
routes. First-time integrations should use [section 3](#3-first-time-or-deferred-integration).

1. Rename the host page route from `prediction/:symbol?` to `predict/:symbol?`
   under the existing locale or basename parent. Update host path constants such
   as `PathEnum.Prediction = "/predict"`, menu hrefs, and page-title mappings.
2. Replace the old `/prediction` base and symbol page routes with replacement
   redirects to `/predict`. Preserve the exact symbol, encoding, locale prefix,
   query parameters, and hash. Keep only the redirect at the old path to avoid
   conflicting page and redirect registrations.
3. Map SDK `/prediction` hrefs to the host's `/predict` routes in the shared
   navigation adapter. Forward `RouteOption.replace`, preserve URL suffixes, and
   leave unrelated paths unchanged. Custom `onPredictionSelect` callbacks must
   also target the host route when they override provider navigation.
4. Use `common.predict` for custom Prediction menu labels, following the
   [Trade menu options](../../../packages/prediction/docs/integration-guide.md#trade-menu).

The SDK still emits `/prediction` hrefs. `RouteOption.name` and the submenu
active key remain `"prediction"`; changing the host URL does not rename those
identifiers.

Use the [navigation compatibility helper and redirect example](../../../packages/prediction/docs/integration-guide.md#navigation-compatibility-and-old-links)
and [provider navigation wiring](../../../packages/prediction/docs/integration-guide.md#provider-navigation-wiring)
for implementation details. For server redirects, retain client-side hash
handling where needed because server handlers cannot read fragments.

## 3. First-time or deferred integration

Start here when upgrading from 3.0.x, 3.1.x, 3.2.x, or 3.3.0 without Prediction
already integrated. Choose one of the following paths. Review
[dependency preparation](#1-prepare-dependencies) for either path; align once to
the final target release, without installing intermediate releases. The numbered
steps below summarize the linked feature guide, not a second integration to run.

### Enable Prediction for the first time

Complete the [Prediction Integration Guide](../../../packages/prediction/docs/integration-guide.md)
using the existing app structure:

1. [Align target dependencies](../../../packages/prediction/docs/integration-guide.md#1-prepare-dependencies-and-the-host-application),
   adding Prediction and only missing direct dependencies used by your integration.
   Keep the existing wallet, locale, broker/network, and provider configuration.
2. [Register the page and routes](../../../packages/prediction/docs/integration-guide.md#2-connect-the-provider-routes-page-and-menu)
   at `/predict` and `/predict/:symbol`, under the existing locale or basename.
   Pass the exact URL `symbol` to `PredictionPage` and accept URL updates after
   selections, refresh, and Back/Forward navigation.
3. [Extend the shared navigation adapter](../../../packages/prediction/docs/integration-guide.md#navigation-callbacks)
   to map SDK `/prediction` hrefs onto `/predict`. Preserve locale, query, hash,
   and `RouteOption.replace`, then connect the callback to the existing provider.
   Do not add a legacy redirect unless the app previously exposed `/prediction`
   URLs; mapping SDK hrefs is still required for every integration.
4. [Add the Prediction menu entry](../../../packages/prediction/docs/integration-guide.md#trade-menu)
   using the host's chosen menu arrangement, without duplicating existing entries.
   Gate custom entries with the effective feature setting.
5. [Guard remembered Perps symbols](../../../packages/prediction/docs/integration-guide.md#guarded-storage-and-migration)
   so Prediction round symbols cannot overwrite them. Migrate a host-owned
   preference only when needed, using the guarded storage helpers.
6. [Check stylesheet alignment](../../../packages/prediction/README.md#stylesheet).
   An existing compatible `@orderly.network/ui/dist/styles.css` import already
   covers Prediction; do not add a duplicate stylesheet import.

Reuse one provider tree, router, and set of routes and menus. Standard Trading,
Markets, and Portfolio components handle their built-in Prediction integrations;
no manual account panels or additional account/data provider are required.

### Defer Prediction

Until its routes and navigation are ready, explicitly disable Prediction while
preserving the other feature settings on the existing provider:

```tsx
<OrderlyAppProvider
  {...appProps}
  features={{
    ...appProps.features,
    prediction: false,
  }}
>
  {children}
</OrderlyAppProvider>
```

Keep an existing `prediction: false` setting when updating dependencies. Gate
custom entries consistently, and provide a host fallback for any existing
Prediction route. This path does not require adding the Prediction page package,
new routes, or menu entries. See [feature visibility](../../../packages/prediction/docs/integration-guide.md#4-configure-feature-visibility-and-regional-restrictions).

## 4. Verify the upgrade

### First-time integration

- [ ] `/predict` and exact-symbol URLs support direct entry, refresh, and
      Back/Forward navigation. URL symbol changes reach `PredictionPage`.
- [ ] SDK hrefs reach `/predict` through the adapter. No legacy redirect was
      added unless the host previously exposed `/prediction` URLs.
- [ ] Replacement navigation avoids an extra history entry. Locales, query
      parameters, and hashes follow the feature guide's navigation contract.
- [ ] Desktop/mobile menus and translated labels work, returning to Perps
      restores a valid Perps symbol, and the page uses the aligned SDK styles.

### Existing route migration

- [ ] `/predict` base and exact-symbol URLs work after the host route change.
- [ ] Existing `/prediction` base and symbol links replace onto `/predict`,
      preserving the symbol, locale prefix, query, and client hash.
- [ ] SDK menu links and custom selection callbacks reach the host route without
      rewriting unrelated paths; replacement navigation does not add an extra
      history entry.
- [ ] Desktop and mobile menus highlight correctly, show translated labels, and
      page-title mappings use the new host path. No raw `common.predict` key appears.

### Deferred integration

- [ ] The existing provider explicitly retains `features.prediction: false`.
- [ ] Built-in and custom Prediction entries are hidden, and any existing
      Prediction route uses the intended host fallback rather than a blank page.
- [ ] Existing Perps navigation and standard account pages still work; no new
      Prediction page dependency, route, or menu is required for deferral.

### All paths

- [ ] The app's typecheck, relevant lint, build, and focused routing checks pass.

When enabling Prediction, use the [full feature verification checklist](../../../packages/prediction/docs/integration-guide.md#5-verify-the-integration)
for Perps storage, disabled behavior, and live account prerequisites. Deferral
requires only the applicable checks above, not Prediction trading validation.
